AnyGameAI 产品与实现要求

规格版本：2026-07-26-r2

一、规范用语与优先级

1. “必须”表示不可省略的验收条件；“应”表示除非存在明确且可验证的技术原因，否则必须实现；“可”表示不影响核心验收的增强项。
2. 本文件是最终产品规格、实现边界、优先级和验收依据。它高于既有代码、旧注释、默认行为、历史实现和提示词；发生冲突时以本文件为准。
3. 安全停止、零误输入、数据完整性和诚实状态高于功能覆盖率、速度、模型指标与界面效果。
4. “完成流程”表示流程已经安全收尾、资源已经释放、结果已经显示且状态回到空闲，不表示必须伪造成功。结果必须区分成功、无需处理、用户取消、部分完成和失败。
5. 无法在当前真实条件下实现的外部能力必须保持最后有效状态并说明原因，不得使用占位资源、虚假结果或降低安全边界来满足表面要求。
6. 只有能够从四个规定按钮之一真实到达，并完整覆盖成功、拒绝、取消、异常、清理和恢复路径的能力才视为已实现。孤立函数、不可达类、仅有界面文案或未接线框架不计入完成度。

二、产品目标与适用边界

1. 产品名称为 AnyGameAI，目标运行环境为 Windows 11 x64、CPython 3.12。
2. AnyGameAI 是面向用户已获授权的本地游戏、单机游戏和测试环境的通用视觉操作与示范学习框架。它通过可靠捕获目标游戏窗口客户区画面、学习用户示范，并使用 Windows 标准用户级键盘鼠标输入操作目标游戏。
3. “通用”表示框架不依赖某款游戏的专用 API，能为不同游戏自动建立相互隔离的档案、观察预处理、动作词表、经验池和策略；不表示未经示范或训练即可精通所有游戏。
4. 核心可用路径是：用户先在“人”模式中提供示范；“升级”流程用有效示范训练并验证该游戏的策略；“AI”模式加载当前有效策略进行受约束推理。没有足够经验或有效模型时必须拒绝自动操作并明确说明。
5. 不同游戏、渲染方式、窗口模式、输入方式和保护机制可能不兼容。程序必须优先支持普通窗口化或无边框窗口；无法可靠捕获、无法可靠识别目标或无法接受标准用户级输入的游戏必须安全拒绝并说明“不兼容”。
6. 程序不得读取或修改游戏进程内存，不得注入 DLL，不得使用驱动、内核组件、网络包修改、协议欺骗、反作弊绕过、验证码绕过或其他规避安全机制的技术。
7. 程序不得要求管理员权限，不得关闭安全软件，不得修改系统 PATH、系统 Python、系统代理、注册表启动项、系统策略或其他与运行无关的系统设置。
8. 除本文件明确允许的依赖、受管理资源和基础模型下载外，画面、操作记录、经验、用户模型、配置和日志默认仅在本机处理；不得上传，不得包含遥测、广告、隐蔽联网或未说明的数据收集。
9. 程序不得把训练损失、画面变化、新颖度、运行时长或其他弱信号冒充游戏胜率、真实奖励或“已学会”。界面和元数据必须使用指标的真实名称。

三、唯一用户操作与四个核心流程

1. 用户只需运行 AnyGameAI.py，不需要执行命令、安装依赖、编辑配置、选择目录、设置环境变量、提供访问令牌或手工启动辅助程序。
2. 程序主界面必须提供四个可单击按钮，标签必须精确为：
   文件
   人
   升级
   AI
3. 单击“文件”：
   - 自动校验全部受管理的不可变文件与运行环境；
   - 自动下载、补全或替换具有真实可信来源的缺失、损坏或不兼容项；
   - 修复或隔离可恢复问题；
   - 完成、取消或失败后安全收尾并回到空闲；
   - 活动期间按 Esc 请求结束当前流程。
4. 单击“人”：
   - 自动选择可靠目标游戏窗口；
   - 进入人工操作模式，由用户直接控制游戏；
   - 程序只观察可靠目标客户区及用户对该目标的有效输入并形成示范经验；
   - 按 Esc 退出人工操作模式、安全提交已完成数据并回到空闲。
5. 单击“升级”：
   - 自动校验、修复、去重、整理和重新索引经验池；
   - 自动获取存在真实可信来源且兼容的基础模型更新；
   - 在有效经验足够时真实训练、验证并原子发布候选模型；
   - 完成、取消或失败后安全收尾并回到空闲；
   - 活动期间按 Esc 请求结束当前流程。
6. 单击“AI”：
   - 自动选择可靠目标游戏窗口；
   - 在全部安全门和兼容性检查通过后进入 AI 自动操作模式；
   - 由当前有效模型控制游戏；
   - 按 Esc 立即请求停止新动作、释放程序保持的输入并回到空闲。
7. 核心流程不得要求连续确认对话框。需要用户处理的阻塞条件必须通过主界面给出一个简短、真实、可操作的中文结果，然后回到空闲。
8. 空闲时按 Esc 不执行破坏性操作，也不退出程序。关闭主窗口才表示退出程序，并且必须先完成安全停止。

四、初始交付、源码与归档约束

1. 每轮对话使用 AnyGameAI.py.zip 作为源码传输容器；ZIP 不是程序运行依赖。
2. 解压后的初始交付必须恰好提供一个普通文件 AnyGameAI.py。它必须是完整、未截断、UTF-8 编码、可由 Python 3.12 直接解析和执行的程序。
3. AnyGameAI.py 顶层导入只能依赖 Python 3.12 标准库。第三方模块必须延迟导入；第三方依赖缺失、损坏或版本不兼容时，程序仍必须能显示主界面并执行“文件”流程。
4. AnyGameAI.py 只能包含实际运行所必需的代码、数据常量和极少量必要实现注释或文档字符串，不得包含要求文本、提示词、教程、示例代码、演示数据、开发计划、测试报告、变更记录、TODO 清单或其他无关内容。
5. 不得把无关文本压缩、编码、加密或拆分后藏入源码；不得嵌入大型模型、第三方安装包或与引导启动无关的二进制负载来规避单文件约束。
6. 不得依赖启动脚本、安装器、用户提供的命令行参数、用户设置的环境变量或手工配置。程序为自身受控子进程使用经严格校验的私有参数或进程间通信属于内部实现，不构成用户操作。
7. 模块导入阶段不得执行网络访问、依赖安装、模型加载、窗口捕获、全局输入钩子、输入发送、训练或其他重量级工作。必须提供明确的 main 入口和 __name__ 保护。
8. 不论从哪个工作目录或含中文、空格、Unicode 的路径启动，程序都必须正确定位自身、真实桌面和管理根目录。
9. 运行过程中允许创建实际运行所需的隔离依赖、模型、数据、缓存、日志、临时文件、有限备份和恢复文件，但这些文件必须遵守本文件的存储、完整性和清理规则。
10. 交付用 AnyGameAI.py.zip 的根目录中必须恰好包含一个名为 AnyGameAI.py 的普通文件，不得包含目录、链接、要求文件、提示词、说明、测试、缓存、字节码、扩展属性侧文件或其他成员。
11. 交付 ZIP 必须使用 Windows 和 Python 标准工具可读取的未加密标准 ZIP 格式，不得使用分卷、密码、非标准压缩方法或自解压格式；归档文件名必须精确为 AnyGameAI.py.zip。

五、引导层、隔离运行环境与文件布局

1. 程序必须优先通过 Windows Known Folder API 获取当前用户真实桌面路径，不得只靠字符串拼接假定 Desktop。只有 API 确实不可用时才可使用可靠回退。
2. 规范管理根目录为：
   <当前用户真实桌面>\AnyGameAI\
3. 程序本体的规范副本、隔离 Python 环境、第三方依赖、受管理资源、基础模型、候选模型、当前模型、游戏档案、经验、配置、缓存、日志及运行生成文件应尽可能统一位于管理根目录。
4. 用户从其他位置启动交付文件时，程序仍须工作。“文件”流程应把当前通过语法、来源和完整性自检的 AnyGameAI.py 以同目录临时文件加原子替换的方式同步为管理根目录中的规范副本，但不得删除或修改用户启动的原文件。
5. 标准库引导层必须由启动 AnyGameAI.py 的 Python 3.12 运行，负责主界面、状态机、文件修复、取消、日志和进程协调。需要第三方依赖的捕获、学习、推理等能力应在管理根目录的隔离运行环境中加载，或由该环境的解释器运行受控子进程。
6. 隔离环境不得污染系统 Python。程序不得向系统 site-packages 写入依赖，不得修改 PATH。若使用 venv，必须验证其解释器、架构、Python ABI 和关键文件；损坏时在受控候选目录重建后原子切换。
7. 管理根目录内部必须按职责隔离，至少覆盖：
   - 引导层规范副本和应用版本元数据；
   - 隔离 Python 环境及锁定依赖；
   - 受可信完整性清单管理的不可变运行资源；
   - 基础模型、候选模型、当前生效模型和有限回滚版本；
   - 按游戏隔离的档案、预处理配置、动作词表和策略；
   - 人工经验、AI 经验、经验索引和隔离区；
   - 下载缓存、事务临时文件和待发布文件；
   - 配置、日志、崩溃恢复信息和有限备份。
8. 必须明确区分：
   - 发行或依赖资源：由可信清单校验，可自动替换；
   - 用户可变数据：档案、经验、用户配置、训练模型和索引，不得被“文件”流程覆盖；
   - 可重建数据：缓存和派生索引，可在保护原始数据后重建；
   - 临时事务数据：未提交前不得被正式流程加载。
9. 不得把模型、经验、依赖或配置写入源码来源目录、当前工作目录或用户不知情的其他位置。
10. 只有无法避免的操作系统临时文件可短暂位于系统临时目录；流程结束、取消、崩溃恢复或下次启动时必须安全清理。
11. 所有结构化数据必须带模式版本、创建程序版本和兼容性元数据。格式升级必须使用兼容读取、原子迁移、备份和失败回滚；不得静默猜测未知版本。
12. 所有自动创建、替换、移动、隔离、清理和解压操作必须先解析规范化路径，并证明最终目标仍位于管理根目录内。必须拒绝借助符号链接、目录连接、挂载点或其他重解析点逃逸。
13. 不得递归删除未解析的变量、通配符、桌面根目录、用户目录、驱动器根目录或整个管理根目录。清理必须针对已验证的具体事务目录或已登记文件。

六、主界面、状态机、取消和单实例

1. 程序启动后必须尽快显示简洁中文图形界面，至少包含四个规定按钮、当前状态、阶段进度和简短结果；不得要求用户查看控制台。
2. 状态至少包括：空闲、文件校验、人工操作、模型升级、AI 操作、正在停止、错误恢复。
3. 同一时刻只能运行一个流程。活动期间必须禁用冲突按钮；快速重复单击不得创建并发任务、重复钩子、重复训练进程或重复输入控制器。
4. 耗时操作必须在受控工作线程或独立工作进程中执行；图形界面主线程不得被网络、校验、安装、训练、推理或大量磁盘操作阻塞。
5. 图形界面只能由主线程更新。后台线程或进程必须通过线程安全有界队列、事件或等价机制报告状态。
6. 所有后台异常必须被捕获、记录并转换为主界面的中文结果；不得让工作线程静默死亡而界面仍显示“进行中”。
7. 在任一活动流程中，Esc 是最高优先级紧急停止命令。即使目标游戏拥有焦点，程序也必须检测 Esc；检测控制层必须在 300 毫秒内发现停止请求。
8. 作为停止命令的 Esc 必须被程序拦截，不得转发给游戏、不得写入训练动作、不得由 AI 生成。空闲时不得保持全局钩子。
9. 捕获、下载、安装、经验整理、训练和推理等长任务必须设置超时，并在可中断边界频繁检查取消信号。不可分割提交完成后必须立刻停止发起新工作。
10. 关闭主窗口时必须先执行与 Esc 等价的安全停止，停止新动作，释放程序拥有的全部输入状态，终止或回收子任务，再退出。
11. 清理必须幂等；重复按 Esc、重复关闭、工作进程异常退出或清理函数被多次调用不得产生新动作、重复提交或破坏有效数据。
12. 程序必须防止同一用户会话中多个实例同时争用模型、经验池、下载事务、钩子或输入控制权。第二实例应安全提示并退出，或只激活已存在实例。
13. 进程级锁必须包含可验证的进程标识、创建时间和实例随机标识。处理陈旧锁前必须确认原拥有者不存在，不能无条件删除。
14. 工作进程必须有心跳或等价存活检测。通信中断、超时或异常退出时，控制层必须切换到零输入、释放程序拥有的输入并回到可恢复状态。

七、目标窗口选择、身份与游戏档案

1. 程序必须在不录制内容和按键的前提下，持续记住最近一个符合条件的外部前台窗口。用户从游戏切换到 AnyGameAI 并单击“人”或“AI”时，应自动把该外部窗口作为目标。
2. AnyGameAI 自身窗口、桌面、任务栏、锁屏、安全桌面、明显的系统外壳、不可见窗口、无有效客户区窗口和无法确认所属进程的窗口不得成为目标。
3. 若没有可靠目标，程序必须保持零输入并回到空闲或安全等待状态，在界面说明原因；不得向当前前台、坐标位置或未知窗口试探性发送输入。
4. 进入人工或 AI 模式后，程序应自动恢复并激活目标窗口，让主界面最小化或退居后台；退出后应恢复主界面及结果显示。
5. 目标身份必须在进入模式时建立，并在运行中复核。身份应综合窗口句柄、进程 ID、进程创建时间、可执行映像标识、窗口类、稳定化标题、客户区尺寸和可取得的文件元数据，避免 PID 复用或标题碰撞。
6. 每款游戏必须有独立档案。动态分数、关卡或状态文字变化不得轻易创建新档案；不同可执行文件或不兼容动作空间不得错误合并。
7. 不同游戏的人工经验、AI 经验、预处理、动作词表、归一化参数、验证集、动作头和当前策略不得混用。只有经过版本校验且与具体动作无关的通用视觉表征可共享。
8. 目标最小化、关闭、失焦、身份变化、客户区无效、客户区尺寸不兼容、会话锁定、安全桌面出现、捕获冻结或捕获内容无法确认时，程序必须立即暂停采集或操作、结束当前片段并释放程序拥有的输入。
9. 只有目标重新满足全部条件后才能建立新片段并恢复；恢复前不得沿用过期帧、过期动作或旧窗口句柄。
10. 客户区坐标、屏幕坐标、逻辑坐标、物理像素、DPI 缩放和多显示器负坐标必须明确转换；不得把标题栏、边框或其他应用区域当作游戏画面。
11. 对独占全屏、硬件叠加、受保护内容或无法通过允许方式稳定捕获的目标，程序必须说明不兼容，不得改用注入、提权或规避保护的方案。

八、“文件”流程

1. 单击“文件”后必须自动执行：
   - 建立并验证管理根目录和必要子目录；
   - 恢复上次中断事务并清理已确认无效的临时文件；
   - 自检并同步 AnyGameAI.py 规范副本；
   - 读取代码内置的可信引导清单；
   - 在具备独立真实性验证条件时获取远程更新清单；
   - 按路径、用途、版本、平台、架构、Python ABI、字节数和 SHA-256 校验受管理不可变文件；
   - 识别缺失、损坏、错误架构、错误 ABI 或版本不兼容项；
   - 下载、补全、隔离或替换有问题且具有真实可信来源的文件；
   - 建立或修复与 Windows x64、Python 3.12 匹配的隔离环境和锁定依赖；
   - 验证归档、模型格式、发行元数据和关键模块可由隔离解释器加载；
   - 原子发布全部通过验证的候选文件；
   - 保留最后有效版本、清理事务并显示结果后回到空闲。
2. 可信清单必须明确区分必需项与可选项，并为每个远程项包含真实版本、用途、平台、架构、Python ABI、长度、SHA-256 和 HTTPS 来源。不得发布占位 URL、全零哈希、虚假签名、虚假版本或不存在的服务。
3. 远程可变清单或高风险可执行资源必须使用独立于下载位置的真实性根，例如代码内置公钥验证的签名、代码内置允许哈希或同等级机制。来自同一未认证位置的文件与哈希不能互相证明可信。
4. 未配置真实且可验证的远程来源时，必须继续完成所有本地校验，并明确显示对应远程资源不可下载；不得把空清单、远程失败或未执行校验显示为全部成功。
5. 网络请求必须使用 HTTPS、正常证书验证、合理的连接与读取超时、下载长度上限、有限重试和退避。可以使用同样受信任且经过哈希验证的镜像回退，不得无限重试。
6. 下载必须先写入受控事务目录。只有来源、长度、SHA-256、平台、架构、ABI、格式和用途全部通过后，才能用同目录原子替换或版本化指针发布。
7. 解压归档前必须拒绝绝对路径、驱动器路径、UNC 逃逸、父目录穿越、重复成员、大小写或 Unicode 归一化冲突、符号链接、重解析点、异常压缩比、超大成员、超大总展开量和同名覆盖。
8. 现有有效版本在新版本完全验证并提交前必须继续可用。更新失败、取消、断电恢复或进程崩溃后必须保留最后有效版本，并清理或隔离半成品。
9. 不得执行由远程文本拼接出的命令，不得使用 eval 或 exec 解释清单，不得使用 shell=True 执行不可信内容，不得下载后静默执行未校验脚本，不得加载来源不可信的 pickle。
10. 第三方依赖必须锁定兼容版本并校验发行文件哈希与实际安装结果。默认只允许 Windows x64、CPython 3.12 可用的预编译 wheel，禁止静默触发本地源码构建。
11. 安装依赖必须由受控子进程完成，命令参数必须使用参数列表，设置超时并捕获输出；取消时停止发起新安装，必要时终止子进程。失败不得污染当前有效隔离环境。
12. 必须验证隔离解释器架构、版本、关键发行包版本、关键模块导入和最小无副作用自检。只看到文件存在不能视为环境完整。
13. 应自动检测可靠 GPU 推理后端；GPU 组件不可用、驱动不匹配或显存不足时必须回退到 CPU，不能阻止主界面和基础流程启动。
14. 可变数据损坏时必须隔离损坏项并在保留原始数据的前提下重建派生索引；不得把用户经验、配置、训练模型或索引误判为发行资源后覆盖。
15. 若清单包含 AnyGameAI.py 自身更新，只能先验证并暂存，再通过安全的退出后替换或下一次启动切换机制更新；不得在执行中截断当前脚本。
16. 无网络时必须保留现有有效安装并显示“网络不可用，保留现有版本”。已有完整环境时，远程不可用不得使本地环境失效。
17. 按 Esc 后必须停止发起新网络请求、新安装和新候选构建，终止可安全终止的子进程，在当前不可分割提交结束后收尾；任何半文件不得成为正式文件。
18. “校验所有文件”只指管理根目录内由可信清单、版本指针或数据索引登记的项目及其必要父目录，不得递归扫描桌面其他内容、用户目录、其他应用目录或未登记文件。未登记的用户可变文件默认不得删除、替换或上传。

九、“人”流程

1. 进入前必须执行快速本地预检：目标可靠、捕获后端可用、输入观察后端可用、档案可写、磁盘空间安全、数据模式兼容。关键组件缺失时应提示先单击“文件”并回到空闲。
2. 人工模式中用户直接控制游戏；程序不得注入、修正、过滤、预测或代替用户的游戏键鼠操作，唯一例外是拦截用作退出命令的 Esc。
3. 程序只能在目标身份仍匹配、目标拥有前台焦点、客户区有效且不是安全桌面时记录目标客户区画面和与该目标有关的用户输入。
4. 目标失焦时必须立即停止捕获可识别内容、停止记录敏感输入并结束当前片段。不得录制其他应用、桌面通知、密码框、登录界面或失焦后的全局输入。
5. 画面、输入状态和事件必须使用单调时钟对齐。记录至少包含：
   - 游戏档案、会话、片段和来源标识；
   - 帧或短帧序列、客户区尺寸、DPI 和预处理元数据；
   - 键盘按下、保持和释放；
   - 鼠标按钮、相对移动、滚轮和客户区归一化位置；
   - 焦点、暂停、分段、丢帧和异常终止信息；
   - 数据模式版本和生成程序版本。
6. 输入观察必须区分物理用户输入与程序注入输入。AI 发送的输入必须带可识别标记并被观察层忽略，防止自我示范和反馈循环。
7. Esc、Windows 键、系统保留键、安全策略禁止的组合键和目标失焦后的事件不得进入可学习动作词表。
8. 动作状态必须基于事件和定期状态校准构建，能表达同时按键、持续保持和释放；丢失事件时必须结束片段，而不是生成错误的长按标签。
9. 经验写入必须采用分块、压缩、校验、追加提交或等价的崩溃可恢复设计；定期原子提交索引，避免一次崩溃损坏整次会话。
10. 人工经验必须标记为用户示范，与 AI 自主经验分开保存，并在训练采样中保持更高可信度。
11. 每个分块必须有长度、哈希、时间范围、帧数、动作统计和模式版本；只允许完整提交的分块进入正式索引。
12. 磁盘空间不足、捕获失败、钩子异常、队列持续溢出或写入错误时必须停止采集、保留已提交数据、释放资源并显示原因，不得继续无限写盘。
13. 按 Esc 后必须停止新采集、结束当前片段、提交最后一个完整可恢复分块、关闭句柄、更新经验索引、恢复主界面并回到空闲。

十、“升级”流程

1. 单击“升级”后必须自动校验和整理经验池，获取存在真实可信来源且兼容的基础模型更新，并在条件满足时用本地有效经验训练、验证和发布候选模型。
2. 升级开始时必须快照当前模型指针、模型元数据和经验索引。任意失败、取消或进程崩溃后必须仍能加载升级前的最后有效模型。
3. 经验池更新至少包括：
   - 校验数据模式、文件哈希、分块边界和索引引用；
   - 隔离损坏、不完整、未知版本或引用丢失的分块；
   - 去重、压缩、重新索引并按游戏档案归类；
   - 严格区分人工经验与 AI 经验；
   - 对动作、场景和时间分布做基本平衡；
   - 生成不会泄漏到训练集的保留验证集；
   - 按磁盘上限执行可恢复保留策略；
   - 优先保留最近有效人工示范、稀有动作和唯一数据。
4. 经验容量必须同时受配置上限、合理磁盘占比和安全剩余空间约束。清理前必须保证新索引已提交且候选删除项仍可证明不是唯一有效副本。
5. 存在经过真实性、哈希、格式和兼容性校验的更新版基础模型时，可先下载到候选区；不得上传本地经验来换取更新。
6. 模型升级必须真实使用本地有效经验学习。最低可用路径为基于人工示范的行为克隆；可结合自监督视觉表征、受约束离线强化学习或其他可验证方法，但不得依赖不存在的奖励。
7. 经验不足时，可只修复经验池或更新可信基础模型，并明确显示“经验不足，未训练”；不得用随机、空白、未经验证或维度猜测的权重替换当前模型。
8. 训练应在独立工作进程中执行，自动选择可靠 GPU 或 CPU 后端，并限制内存、显存、线程、批大小、运行时长、临时空间和磁盘写入；主界面和 Esc 检测必须持续响应。
9. 训练必须可复现地记录随机种子、数据快照、核心超参数和软件兼容版本。训练进程不得修改当前模型指针。
10. 候选模型至少必须通过：
   - 文件格式和数据模式兼容；
   - 权重数值有限且能够安全加载；
   - 输入输出尺寸、颜色与缩放预处理、帧序列和动作词表一致；
   - 保留集模仿指标达到明确最低阈值，且在可比较时不明显劣于当前模型；
   - 中性动作、禁止动作掩码、同时按键和释放语义检查；
   - 短时推理稳定性、截止时间、内存和资源上限检查；
   - 模型与对应档案、动作头和归一化元数据绑定检查。
11. 模型文件必须采用安全、明确的格式，例如 ONNX、safetensors 或经严格验证的自有数值格式；不得反序列化来源不可信的 pickle。
12. 只有全部验证通过的候选模型才能通过同目录原子指针切换成为当前模型。必须保留有限数量的最后有效版本并支持自动回滚。
13. 升级元数据必须记录模型版本、父版本、训练数据摘要、动作词表、随机种子、核心超参数、验证结果、兼容模式和发布事务标识。
14. 按 Esc 后必须停止读取新批次并请求训练进程有序退出；超过合理宽限期可终止训练进程。候选半成品不得成为当前模型，原模型和已提交经验必须保持有效。
15. 升级完成后必须显示真实结果，例如“经验池已更新，经验不足，未训练”“候选未通过验证，保留原模型”或“模型已升级”，然后回到空闲。

十一、“AI”流程

1. 进入前必须快速验证关键依赖、目标身份、游戏档案、当前模型、预处理元数据、动作词表、动作安全掩码、捕获后端和输入后端。
2. 任何关键项缺失、损坏、未知版本或不兼容时，必须保持零输入，说明应执行“文件”“人”或“升级”，然后回到空闲。
3. 程序必须使用与训练完全一致的客户区捕获、颜色处理、缩放、宽高比策略、归一化、帧序列长度和动作编码；不得静默猜测或自动改变模型输入含义。
4. 推理循环必须使用单调时间戳、帧年龄和截止时间。帧过旧、捕获失败、画面冻结、队列过载、模型异常、输出非有限、置信度低于安全阈值或推理严重超时时，必须输出中性动作并释放程序拥有的输入。
5. 键鼠输入只能通过 Windows 标准用户级接口发送，并且只能在目标身份仍匹配、目标为前台、客户区有效且不是安全桌面时发送；不得向后台、未知窗口、桌面或系统界面广播。
6. 所有注入事件必须使用唯一标记。输入控制器必须单独维护“程序已按下”的键和鼠标按钮，不得把用户物理保持状态误认为程序所有。
7. 停止或异常时只释放程序确实拥有的注入状态，不得为用户物理按键伪造无所有权的释放事件。释放过程必须幂等并在发送前再次验证安全上下文。
8. 动作层必须正确实现按下、保持、释放、同时按键、鼠标相对移动、鼠标按钮和滚轮，并限制速率、持续时间、坐标、单帧变化和最大连续保持时间。
9. 必须硬性屏蔽 Esc、Windows 键、Alt+F4、Ctrl+Alt+Delete、任务切换、系统电源相关组合键及其他会操作系统、关闭程序或离开目标游戏的危险动作。模型输出不得覆盖硬性安全掩码。
10. 目标失焦、最小化、关闭、身份变化、客户区变化不兼容、捕获冻结、模型报错、工作进程通信中断、用户按 Esc、程序关闭或会话锁定时，必须先停止产生新动作，再释放程序拥有的全部键和鼠标按钮。
11. AI 模式产生的观察和动作可写入独立经验区，但必须标记策略版本、置信度、来源、会话边界和安全降级事件，不得伪装成人工示范。
12. 没有可靠游戏奖励时不得构造胜负标签。画面变化、新颖度、动作一致性和持续时间等通用弱信号必须单独命名并与真实奖励分开。
13. 推理频率应根据硬件、模型延迟和游戏自适应，优先保证低延迟、安全看门狗和可取消性；不得忙等待长期占满 CPU。
14. 按 Esc 后必须停止产生新动作、尽快释放程序拥有的输入、结束经验片段、关闭工作资源、恢复主界面并回到空闲。

十二、观察、动作与通用学习表示

1. 观察表示必须支持不同客户区分辨率、DPI 和宽高比，并记录从客户区物理像素到模型输入的确定性变换。
2. 模型必须使用短时间帧序列、显式时序状态或等价机制，避免只根据单帧猜测运动方向。
3. 预处理必须避免无意拉伸导致控制含义变化；裁剪、填充、缩放和颜色顺序必须写入版本化元数据并在训练与推理间一致。
4. 动作词表必须从硬性安全白名单和人工示范中建立，支持同时按键与持续动作；不得把全部虚拟键、系统键或未见动作无条件开放给模型。
5. 鼠标位置和位移必须在客户区坐标内归一化，模型输出必须经限幅、速率限制和目标边界转换后才能发送。
6. 新游戏第一次人工会话必须能自动建立档案、动作统计、预处理元数据和经验索引，不得要求用户编写游戏插件。
7. 跨游戏迁移只能共享与具体动作无关、经过版本校验的表征；每个游戏必须保留独立动作映射、归一化、验证集和当前策略。
8. 所有训练和推理元数据必须足以判断兼容性。发现不兼容时必须拒绝加载并回退到最后有效模型，不能猜测维度或静默转换。

十三、数据完整性、事务与恢复

1. 模型、清单、经验分块、经验索引、配置、版本指针和档案元数据必须带格式版本、长度或边界校验以及适用的内容哈希。
2. 正式状态必须通过“写临时文件—刷新—校验—同目录原子替换”或版本化目录加原子指针发布；临时文件不得被正常加载。
3. 涉及多个文件的事务必须有事务标识、准备状态和提交记录。启动时必须能判断事务是已提交、可恢复还是应隔离。
4. 下载、训练、经验整理和 AI 输入控制不得并发运行；人工采集与会修改同一经验索引的整理流程也不得并发。
5. 捕获、预处理、推理、输入和写盘必须使用有界队列。消费者变慢时应丢弃过期帧、结束不可靠片段或施加背压，禁止无限增长内存。
6. 写共享资源必须持有进程级锁。锁超时必须转为错误状态，不得绕过互斥继续写入。
7. 启动时必须恢复或清理上次中断留下的临时下载、候选环境、候选模型、未提交分块和陈旧事务，同时保留有限诊断信息。
8. 外部进程、网络、线程、进程间通信、文件句柄、窗口句柄、捕获对象、钩子和输入状态必须有明确所有权、超时、取消和 finally 清理。
9. 不得因为索引损坏而直接删除唯一经验文件；不得因为候选模型失败而删除唯一当前模型；不得因为缓存清理而越过登记边界删除用户文件。

十四、性能与资源边界

1. 在未安装任何项目第三方依赖的首次启动中，主界面应尽快可交互；普通机器目标为 3 秒内。
2. GUI 状态更新、Esc 检测和输入安全看门狗不得依赖低帧率训练或推理循环。
3. 应根据硬件在约 5 至 60 次每秒范围内自适应捕获和操作频率；默认目标可为 20 次每秒，但不得牺牲停止能力和帧新鲜度。
4. 下载并发、重试次数、子进程数、数据加载线程、训练线程、队列长度、缓存、日志、临时文件和备份数量必须有明确上限。
5. 经验池上限必须取配置上限、合理磁盘占比和预留安全空间后的较小值；接近安全线时必须停止采集而不是占满系统盘。
6. CPU、GPU、内存、显存或磁盘资源不足时必须自动降级、减小负载或安全结束，不得让系统长期失去响应。
7. 训练和推理不得无限运行。训练必须有预算和进度心跳；推理必须有截止时间和冻结检测。

十五、安全、隐私与日志

1. 所有远程地址、清单字段、版本、归档成员名、模型元数据和路径都必须作为不可信数据验证，防止命令注入、路径穿越、资源耗尽和任意文件覆盖。
2. 不得硬编码私钥、访问令牌、个人目录、测试账号、仅开发者机器可用的路径或不可验证的内部地址。
3. 不得使用不安全 TLS 选项，不得忽略证书错误，不得为下载全局关闭代理、证书或安全检查。
4. 任何下载、模型、经验或归档都不得仅凭扩展名可信而执行、导入或反序列化。
5. 程序必须在安全桌面、锁屏、远程会话变化、用户会话退出或无法确认前台目标时停止捕获敏感内容和发送输入。
6. 不得录制或上传其他应用内容；不得设计在目标失焦后继续采集全局敏感输入的隐藏模式。
7. 日志必须滚动并限制单文件和总大小；不得记录原始画面、完整按键序列、访问令牌、下载签名参数、完整个人路径或与诊断无关的隐私内容。

十七、验收场景

1. 全新 Windows 11 x64 用户目录中只有 AnyGameAI.py，未安装项目第三方包且网络断开；运行后仍能显示四个规定按钮和中文状态。

5. 打开普通窗口化测试游戏，从游戏切换到 AnyGameAI 后单击“人”，程序能自动回到该窗口，只记录客户区画面和用户对该目标的动作；按 Esc 后经验可恢复且界面回到空闲。
6. 人工模式中切换到其他应用时立即停止采集敏感输入并结束片段；切回目标后只能以新片段继续，不把其他应用画面或输入写入经验。

9. 单击“AI”只在目标身份可靠、位于前台且全部模型兼容性检查通过时产生受限动作；目标失焦、关闭、画面冻结、模型异常、通信中断或按 Esc 时，程序拥有的输入全部被释放。
10. AI 注入输入不会被人工输入观察层当作用户示范；停止时不会为用户物理按住的键伪造无所有权释放。
11. 对不兼容或受保护目标，程序保持零输入、说明不兼容，且不尝试注入、提权或绕过。
12. 快速重复按按钮、重复按 Esc、关闭窗口、运行第二实例、磁盘空间不足、索引损坏和网络超时不会导致无限等待、越界删除、数据损坏或残留输入。
13. 在中文用户名、含空格路径、OneDrive 重定向桌面、不同 DPI 和多显示器环境中，管理目录和客户区坐标仍正确。
