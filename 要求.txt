AnyGameAI 产品与实现要求

一、规范用语

1. “必须”表示不可省略的验收条件。
2. “应”表示除非存在明确、可验证的技术原因，否则必须实现。
3. “可”表示不影响核心验收的增强项。
4. 本文件高于既有代码中的注释、旧实现、默认行为和提示词；冲突时以本文件为准。

二、产品目标与适用边界

1. 产品名称为 AnyGameAI，目标运行环境为 Windows 11 x64、CPython 3.12。
2. AnyGameAI 是面向用户已获授权的本地游戏、单机游戏和测试环境的通用视觉操作与示范学习框架。它通过捕获可靠目标游戏窗口的客户区画面、学习用户示范，并使用 Windows 标准用户级键盘鼠标输入操作游戏。
3. “通用”表示框架不依赖某款游戏的专用 API，能为不同游戏自动建立相互隔离的档案、动作词表、经验池和策略；不表示未经示范或训练即可精通所有游戏，也不允许用随机动作、规则占位或伪造指标宣称已经学会。
4. 不同游戏、渲染方式、输入方式和保护机制可能不兼容。程序必须优先支持普通窗口化或无边框窗口；无法可靠捕获或无法接受标准用户级输入的游戏必须安全拒绝并说明“不兼容”，不得规避保护机制。
5. 程序不得读取或修改游戏进程内存，不得注入 DLL，不得使用驱动、内核组件、网络包修改、协议欺骗、反作弊绕过、验证码绕过或其他规避安全机制的技术。
6. 程序不得要求管理员权限，不得关闭安全软件，不得修改系统 PATH、系统 Python、系统代理、注册表启动项或其他与运行无关的系统设置。
7. 除明确的文件下载外，画面、操作记录、经验、模型、配置和日志默认仅在本机处理；不得上传，不得包含遥测、广告、隐蔽联网或未说明的数据收集。

三、用户操作与核心流程

1. 用户只需运行 AnyGameAI.py，然后使用主界面的四个按钮或 Esc：
   - 单击“文件”：自动校验全部受管理文件，下载、补全或替换缺失及损坏文件，处理完成后结束本流程；按 Esc 取消并安全结束本流程。
   - 单击“人”：进入人工操作模式，由用户控制目标游戏并形成示范经验；按 Esc 退出人工模式。
   - 单击“升级”：自动升级可验证的基础模型、整理经验池，并在有足够有效经验时训练、验证和发布候选模型；处理完成后结束本流程；按 Esc 取消并安全结束本流程。
   - 单击“AI”：进入 AI 自动操作模式，由当前有效模型控制目标游戏；按 Esc 退出 AI 模式。
2. 核心流程不得要求用户执行命令、安装依赖、编辑配置、选择目录、输入访问令牌或连续确认对话框。
3. 无法完成某流程时，程序必须保持数据和输入安全，显示简短、诚实、可操作的中文状态，并回到空闲状态；不得伪装成成功。

四、初始交付与单文件约束

1. 每轮对话使用 AnyGameAI.py.zip 作为源码传输容器；ZIP 不是运行依赖。解压后的初始交付只提供 AnyGameAI.py 一个文件。
2. AnyGameAI.py 必须是 UTF-8 编码、可由 Python 3.12 直接解析和执行的完整程序，不依赖启动脚本、安装器、用户提供的命令行参数、环境变量或手工配置。
3. AnyGameAI.py 顶层导入只能依赖 Python 3.12 标准库。第三方模块必须延迟导入；依赖未安装或损坏时，程序仍必须能启动主界面并执行“文件”流程。
4. AnyGameAI.py 只能包含程序实际运行所必需的代码、数据常量和极少量必要实现注释，不得包含说明文档、教程、示例代码、演示数据、开发日志、变更记录、测试报告、TODO 清单、要求文本或其他无关内容。
5. 运行过程中允许程序创建实际运行所需的目录、隔离依赖、模型、数据、缓存、日志、临时文件、备份和恢复文件。
6. 不论从哪个工作目录或含中文、空格、Unicode 的路径启动，程序都必须正确定位自身和数据目录。
7. 交付用 AnyGameAI.py.zip 的根目录中必须恰好包含一个普通文件 AnyGameAI.py，不得包含目录、符号链接、要求文件、提示词、说明、测试、缓存、字节码或其他文件。

五、文件布局与存储原则

1. 程序必须优先通过 Windows Known Folder API 获取当前用户真实桌面路径，不得只靠字符串拼接假定“Desktop”；仅在 API 不可用时使用可靠回退。
2. 规范管理根目录为：
   <当前用户真实桌面>\AnyGameAI\
3. 程序本体的规范副本、隔离运行环境、依赖、模型、数据、经验、配置、缓存、日志和运行生成文件应统一位于管理根目录。用户从其他位置启动交付文件时，程序仍须工作；“文件”流程应把当前通过自检的 AnyGameAI.py 以原子方式同步为管理根目录中的规范副本，但不得擅自删除用户启动的原文件。
4. 管理根目录内部必须按职责隔离，至少覆盖：
   - 隔离 Python 环境和第三方依赖；
   - 受完整性清单管理的只读运行资源；
   - 基础模型、候选模型和当前生效模型；
   - 按游戏隔离的档案与配置；
   - 人工经验、AI 经验和经验索引；
   - 下载缓存、临时文件和隔离区；
   - 日志、崩溃恢复信息和有限数量的备份。
5. 不得把依赖安装到系统 Python，不得把模型或经验写入源码来源目录、当前工作目录或用户不知情的其他位置。
6. 只有无法避免的操作系统临时文件可短暂位于系统临时目录；流程结束、取消或下次启动时必须清理。
7. 可变用户数据与受完整性清单管理的资源必须分开。“文件”流程不得把经验、用户配置、用户训练模型或索引误判为发行资源后覆盖。
8. 所有结构化数据必须带模式版本；格式升级必须使用原子迁移、备份、兼容读取或失败回滚。
9. 所有自动创建、替换、移动、隔离和清理操作都必须先解析规范化路径，并证明目标位于管理根目录内；不得跟随重解析点、连接或符号链接逃逸。

六、主界面与状态机

1. 程序启动后必须尽快显示简洁的中文图形界面，至少包含四个可单击按钮，标签必须精确为：
   文件
   人
   升级
   AI
2. 界面必须显示当前状态、阶段进度和简短结果；不得要求用户查看控制台。
3. 状态至少包括：空闲、文件校验、人工操作、模型升级、AI 操作、正在停止、错误恢复。
4. 同一时刻只能运行一个流程。活动期间必须禁用会产生冲突的按钮，重复单击不得创建并发任务。
5. 耗时操作必须在受控工作线程或独立工作进程中执行；图形界面主线程不得被网络、校验、安装、训练、推理或大量磁盘操作阻塞。
6. 图形界面只能由主线程更新。后台线程或进程必须通过线程安全队列、事件或等价机制报告状态。
7. 空闲时按 Esc 不执行破坏性操作。活动流程中按 Esc 必须请求结束当前流程，在安全收尾后回到空闲，而不是直接崩溃或粗暴退出整个程序。
8. 在人工或 AI 模式中，即使目标游戏拥有焦点，程序也必须能识别 Esc。Esc 是最高优先级紧急停止键，不得写入训练动作，也不得由 AI 发送给游戏。
9. 停止请求必须由控制层在 300 毫秒内发现；捕获、下载、训练和推理等长任务必须设置超时，并在可中断边界频繁检查取消信号。
10. 关闭主窗口时必须先执行与 Esc 等价的安全停止，释放程序保持的全部按键和鼠标按钮，再退出。
11. 程序必须防止同一用户会话中多个实例同时争用模型、经验池、下载事务或输入控制权；第二实例应安全提示并退出或只激活现有实例。
12. 所有后台异常必须被捕获、记录并转换为中文状态；不得让后台任务静默死亡而界面仍显示“进行中”。

七、目标游戏窗口与游戏档案

1. 程序必须持续记住最近一个符合条件的外部前台窗口。用户从游戏切换到 AnyGameAI 并单击“人”或“AI”时，应自动把该外部窗口作为目标。
2. AnyGameAI 自身窗口、桌面、任务栏、锁屏、安全桌面、不可见窗口、无有效客户区窗口和明显的系统外壳不得成为目标。
3. 若没有可靠目标，程序必须保持零输入并回到空闲或安全等待状态，在界面说明原因，不得向未知窗口发送输入。
4. 进入人工或 AI 模式后，程序应自动恢复目标窗口，并让主界面最小化或退居后台；退出后应恢复主界面及状态显示。
5. 每款游戏必须有独立档案。档案标识应综合可稳定取得的进程映像标识、窗口类、规范化标题、客户区尺寸和可执行文件元数据，同时避免仅因分数、关卡或动态标题变化而建立新档案。
6. 不同游戏的经验和策略不得错误混用。可共享经过验证、与动作无关的通用视觉表征；动作头、动作词表、归一化参数、经验索引和当前策略必须按档案隔离。
7. 目标窗口最小化、关闭、失焦、被遮蔽到无法可靠捕获、客户区尺寸发生不兼容变化、会话锁定或安全桌面出现时，程序必须暂停捕获或操作、释放输入，并等待可靠恢复或安全结束。
8. 客户区坐标、屏幕坐标、DPI 缩放和多显示器坐标必须明确转换；不得把窗口边框、标题栏或其他应用区域当作游戏画面。

八、“文件”按钮流程

1. 单击“文件”后，程序必须自动执行完整性与修复流程：
   - 建立管理根目录及必要子目录；
   - 自检并同步 AnyGameAI.py 规范副本；
   - 读取内置可信清单，并在具备真实性验证条件时获取更新清单；
   - 校验受管理文件的路径、版本、用途、平台、架构、Python ABI、字节数和 SHA-256；
   - 识别缺失、损坏、版本不兼容或错误架构文件；
   - 下载、补全或替换有问题的文件；
   - 建立或修复与 Python 3.12、Windows x64 匹配的隔离环境和锁定依赖；
   - 校验下载结果、归档、模型格式和关键模块可加载性；
   - 原子发布新文件、清理临时文件并保留最后一个可用版本；
   - 显示成功、无需更新、取消、部分完成或失败结果，然后回到空闲。
2. 清单必须明确区分必需项和可选项，并包含真实版本、平台、Python ABI、文件长度、SHA-256、HTTPS 下载源和用途。不得发布占位 URL、虚假哈希、虚假签名或不存在的服务。
3. 未配置真实且可验证的远程来源时，程序必须诚实报告对应资源不可下载，并继续校验现有本地文件；不得把远程失败或空清单显示为全部成功。
4. 网络请求必须使用 HTTPS、正常证书验证、合理的连接与读取超时、长度上限、有限重试和退避。可使用经过校验的镜像回退，但不得无限重试。
5. 远程清单和高风险可执行资源必须具有独立于下载位置的可验证真实性根，例如代码内置公钥或代码内置允许哈希；不得把来自同一未认证位置的文件与哈希视为充分验证。
6. 下载必须先写入受控临时文件；支持安全续传时可续传。只有长度、SHA-256、平台、格式和用途全部通过后，才能用同目录原子替换发布。
7. 解压归档前必须拒绝绝对路径、父目录穿越、重复成员、符号链接或重解析点、目录逃逸、异常压缩比、超大展开和同名覆盖。
8. 现有有效版本在新版本完全验证前必须继续可用。更新失败或取消时必须保留最后可用版本并清理或隔离半成品。
9. 不得执行从远程文本拼接出的命令，不得用 eval/exec 解释清单，不得下载后静默执行未校验脚本，不得加载来源不可信的 pickle。
10. 依赖必须锁定兼容版本并验证实际安装结果。应只安装 Windows x64、Python 3.12 可用的预编译轮子，禁止默认触发本地源码构建或把依赖写入系统 Python。
11. 应自动检测可靠的 GPU 推理后端；GPU 组件不可用时必须回退到 CPU，不得阻止主界面和基础功能启动。
12. 可变数据损坏时必须隔离损坏项并重建索引，不得直接删除唯一经验副本或唯一有效模型。
13. 若清单包含 AnyGameAI.py 自身更新，只能验证并暂存，再通过安全的退出后替换机制更新；不得在执行中截断当前脚本。
14. 无网络时必须保留现有有效安装并显示“网络不可用，保留现有版本”。已有完整环境时，远程不可用不得使本地环境失效。
15. 按 Esc 后必须停止发起新下载和新安装，终止可安全终止的子进程，在当前不可分割写入结束后收尾；不得把半文件当作正式文件。

九、“人”按钮流程

1. 单击“人”后，程序必须进入人工操作模式，由用户直接控制可靠目标游戏；程序不得注入、修正、过滤或代替用户的游戏键鼠操作。
2. 进入前必须执行快速本地预检。关键组件缺失时应提示先单击“文件”并回到空闲，不能崩溃或暗中运行不完整流程。
3. 人工模式的学习职责是观察目标游戏客户区，并只在目标拥有前台焦点时记录与游戏有关的用户键鼠状态；不得录制其他应用、桌面通知、密码框或失焦后的用户输入。
4. 画面、动作和时间必须使用单调时钟对齐。记录至少包含：
   - 游戏档案、会话和片段标识；
   - 帧或短帧序列、客户区尺寸和预处理元数据；
   - 键盘按下、保持和释放；
   - 鼠标按钮、相对移动、滚轮和归一化位置；
   - 焦点、暂停、分段和异常终止信息；
   - 数据模式版本和生成程序版本。
5. Esc、系统键和安全策略禁止的组合键不得进入可学习动作词表。
6. 经验写入必须采用分块、压缩、追加提交或等价的崩溃可恢复设计，定期原子提交索引，避免一次崩溃损坏整次会话。
7. 失去目标焦点时必须立即停止采集敏感输入并结束当前片段；可靠恢复焦点后可开始新片段。
8. 人工经验必须标记为用户示范，与 AI 自主经验分开保存，并在训练采样中具有更高可信度。
9. 磁盘空间不足、捕获失败、钩子异常或写入错误时必须停止采集、保留已提交数据、释放资源并显示原因，不得继续无限写盘。
10. 按 Esc 后必须停止采集、提交最后一个完整可恢复分块、关闭句柄、更新经验索引、恢复主界面并回到空闲。

十、“升级”按钮流程

1. 单击“升级”后，程序必须自动校验和整理经验池，获取可验证且兼容的基础模型更新，并在条件满足时用本地有效经验训练、验证和发布候选模型；完成后回到空闲。
2. 升级开始时必须快照当前模型指针、模型元数据和经验索引；任意失败或取消后必须仍能使用升级前版本。
3. 经验池更新至少包括：
   - 校验模式、文件哈希、分块边界和引用关系；
   - 隔离损坏或不完整分块；
   - 去重、压缩、重新索引并按游戏归档；
   - 区分人工经验与 AI 经验；
   - 对动作、场景和时间分布做基本平衡；
   - 按磁盘上限执行可恢复保留策略；
   - 优先保留最近有效人工示范和稀有动作数据。
4. 经验容量必须同时受配置上限、合理磁盘占比和安全剩余空间约束；清理前必须保证索引与文件一致，不得删除唯一有效模型或唯一经验副本。
5. 存在经过真实性、哈希、格式和兼容性校验的更新版基础模型时，可先下载到候选区；不得上传本地经验来换取更新。
6. 模型升级必须真实使用本地有效经验学习，最低可用路径为基于人工示范的行为克隆；可结合自监督表征学习、受约束离线强化学习或其他可验证方法。
7. 经验不足时，可只修复经验池或更新可信基础模型，并明确显示“经验不足，未训练”；不得用随机、空白或未经验证的权重替换当前模型。
8. 训练应在独立工作进程中执行，自动选择可靠 GPU 或 CPU 后端，限制内存、显存、线程、批大小、运行时长和磁盘占用；主界面和 Esc 检测必须持续响应。
9. 必须划分不会泄漏到训练集的验证样本。候选模型至少通过：
   - 文件格式和数据模式兼容；
   - 权重数值有限且可成功加载；
   - 输入输出尺寸、预处理和动作词表一致；
   - 保留集模仿指标不低于允许阈值，且不明显劣于当前模型；
   - 短时推理稳定性、延迟和资源上限；
   - 禁止动作掩码和中性动作检查。
10. 模型文件必须采用安全、明确的格式，例如 ONNX、safetensors 或受严格校验的自有数值格式；不得反序列化来源不可信的 pickle。
11. 只有候选模型全部通过后才能原子切换“当前模型”指针；必须保留有限数量的最后可用版本，以便自动回滚。
12. 升级元数据必须记录模型版本、训练数据摘要、动作词表、随机种子、核心超参数、验证结果和兼容模式；这些运行元数据不得写成长篇说明塞入 AnyGameAI.py。
13. 按 Esc 后必须停止读取新批次并请求训练进程有序退出；超过合理宽限期可终止训练进程。候选半成品不得成为当前模型，原模型和已提交经验必须保持有效。

十一、“AI”按钮流程

1. 单击“AI”后，程序必须进入 AI 自动操作模式，由当前有效模型控制可靠目标游戏。
2. 进入前必须快速验证关键依赖、目标档案、当前模型、预处理元数据、动作词表和输入后端。任何关键项缺失或不兼容时，必须保持零输入并说明应执行“文件”或“升级”。
3. 程序必须使用与训练一致的客户区捕获、颜色处理、缩放、宽高比策略、归一化、帧序列长度和动作编码。
4. 推理循环必须包含单调时间戳和截止时间。帧过旧、捕获失败、画面冻结、模型异常、置信度低于安全阈值或推理严重超时时，必须输出中性动作并释放已有输入。
5. 键鼠输入只能通过 Windows 标准用户级接口发送，并且只能在目标身份仍匹配、目标为前台且客户区有效时发送；不得向后台或未知窗口广播。
6. 动作层必须正确实现按下、保持、释放、鼠标相对移动、鼠标按钮和滚轮，并限制速率、持续时间、坐标和单帧变化，防止失控输入。
7. 必须硬性屏蔽 Windows 键、Esc、Alt+F4、Ctrl+Alt+Delete、任务切换、系统电源相关组合键及其他会操作系统或离开目标游戏的危险动作。
8. 目标失焦、最小化、关闭、身份变化、捕获冻结、模型报错、工作进程通信中断、用户按 Esc、程序关闭或会话锁定时，必须先停止产生新动作并释放程序保持的全部键和鼠标按钮。
9. AI 模式产生的观察和动作可写入独立经验区，但必须标记策略版本、置信度、来源和会话边界，不得伪装成人工示范。
10. 没有可靠游戏奖励时不得凭空构造“胜利”标签。可记录画面变化、新颖度、持续时间等通用弱信号，但必须与真实奖励明确区分。
11. 推理频率应根据硬件和游戏自适应，优先保证低延迟、安全看门狗和可取消性；不得用忙等待长期占满 CPU。
12. 按 Esc 后必须停止产生新动作、立即全量释放输入、结束经验片段、关闭工作资源、恢复主界面并回到空闲。

十二、通用学习与动作表示

1. 观察表示必须支持不同分辨率、DPI、窗口边框和宽高比，并明确区分客户区坐标与屏幕坐标。
2. 模型必须使用短时间帧序列或等价时序状态，避免只根据单帧猜测运动方向。
3. 动作词表必须从安全白名单和人工示范中建立，支持同时按键与持续动作；不得把所有系统按键无条件开放给模型。
4. 新游戏第一次人工会话必须能自动建立档案、动作统计和预处理元数据，不得要求用户编写游戏插件。
5. 跨游戏迁移只能共享与具体动作无关、经过版本校验的表征；每个游戏必须保留独立动作映射、归一化和当前策略。
6. 所有训练和推理元数据必须足以判断兼容性。发现不兼容时必须拒绝加载并回退到最后可用模型，不能猜测维度或静默转换。
7. 模型置信度、验证分数和弱奖励只能用于其真实定义的用途；不得把训练损失包装成游戏胜率。

十三、并发、可靠性与恢复

1. 下载、模型训练、经验整理和 AI 输入控制不得并发运行。
2. 捕获、推理和写盘必须使用有界队列；消费者变慢时应丢弃过时帧或施加背压，禁止无限增长内存。
3. 模型、清单、经验索引、配置和版本指针必须使用同目录临时文件加原子替换；必要时刷新文件与目录元数据。
4. 写共享资源必须使用进程级锁。处理陈旧锁前必须验证拥有进程、启动时间或唯一实例标识，不能无条件删除。
5. 启动时必须恢复或清理上次中断留下的临时下载、候选模型、未提交分块和陈旧事务，同时保留有限诊断信息。
6. 日志必须滚动并限制总大小；不得记录原始画面、访问令牌、远程签名参数、完整个人路径或与诊断无关的按键明文。
7. 任意退出路径都必须进行幂等清理。重复停止、重复关闭或重复释放输入不得报错或再次产生动作。
8. 外部进程、网络、线程、进程间通信、文件句柄、窗口句柄、捕获对象和输入状态必须有明确所有权、超时、取消和 finally 清理。

十四、性能与资源

1. 在没有任何项目第三方依赖的首次启动中，主界面应尽快出现；普通机器目标为 3 秒内可交互。
2. GUI 状态更新和 Esc 检测不得依赖低帧率训练或推理循环。
3. 应根据硬件在约 5 至 60 次每秒范围内自适应捕获和操作频率；默认目标可为 20 次每秒，但不得牺牲安全停止能力。
4. 下载并发、重试次数、数据加载进程、训练线程、缓存、日志、临时文件和备份数量必须有明确上限。
5. 经验池上限应取配置上限、合理磁盘占比和预留安全空间后的较小值；接近安全线时必须停止采集而不是占满系统盘。
6. CPU、GPU、内存或磁盘资源不足时必须自动降级、减小负载或安全结束，不得让系统长期失去响应。

十五、安全与隐私

1. 所有远程地址、版本、清单字段和路径都必须作为不可信数据校验，防止命令注入、路径穿越、资源耗尽和任意文件覆盖。
2. 不得硬编码私钥、访问令牌、个人目录、测试账号、仅开发者机器可用的路径或不可验证的内部地址。
3. 不得使用不安全 TLS 选项，不得忽略证书错误，不得为下载全局关闭代理或安全检查。
4. 任何下载、模型、经验或归档都不得仅凭扩展名可信而执行或反序列化。
5. 程序必须在安全桌面、锁屏、远程会话变化、用户会话退出或无法确认前台目标时停止发送输入。
6. 不得录制或上传其他应用内容；不得设计可在目标失焦后继续采集全局敏感输入的模式。

十六、错误呈现

1. 面向用户的状态必须简短、中文、真实且可操作，例如“网络不可用，保留现有版本”“缺少运行文件，请先单击文件”或“目标不兼容，未发送输入”。
2. 技术细节写入有大小限制的日志；界面不得显示完整堆栈，也不得用连续弹窗阻塞自动流程。
3. 可选资源失败不得伪装成全部成功；必需资源失败不得允许进入依赖该资源的模式。
4. 每个流程结束必须区分成功、无需处理、用户取消、部分完成和失败。

十七、验收场景

1. 全新 Windows 11 x64 用户目录中只有 AnyGameAI.py，未安装项目第三方包且网络断开；运行后仍能显示四个按钮和状态。
2. 单击“文件”能建立桌面 AnyGameAI 目录并完成本地校验。删除一个有真实来源的受管理文件后再次单击能补全；篡改文件后能按长度和 SHA-256 识别并原子替换。
3. 下载中按 Esc 或强制结束进程，再次启动不会把半文件当成有效文件，也不会破坏此前有效版本。
4. 打开普通窗口化测试游戏，从游戏切换到 AnyGameAI 后单击“人”，程序能自动回到该窗口，只记录其客户区画面和人工动作；按 Esc 后经验可恢复且界面回到空闲。
5. 人工模式中切换到其他应用时停止采集敏感输入；切回目标后以新片段继续，不把其他应用画面写入经验。
6. 单击“升级”能校验和更新经验索引；有足够人工经验时产生经过验证的候选模型并原子发布。升级中按 Esc 后旧模型仍可加载。
7. 单击“AI”只在目标窗口身份可靠且位于前台时产生受限动作；目标失焦、关闭、画面冻结、模型异常或按 Esc 时，所有保持输入均被释放。
8. 对不兼容或受保护目标，程序保持零输入、说明不兼容，且不尝试注入、提权或绕过。
9. 快速重复按按钮、重复按 Esc、关闭窗口、运行第二实例、磁盘空间不足、模型损坏和网络超时均不会导致无限等待、越界删除、数据损坏或残留按键。
10. 在中文用户名、含空格路径、OneDrive 重定向桌面、不同 DPI 和多显示器环境中，目录和客户区坐标仍正确。
11. 检查 AnyGameAI.py，确认其是完整可执行代码，且不包含说明文档、示例、伪实现、测试报告、要求文本或无关内容。

十八、实现完成度原则

1. 所有核心路径必须使用真实实现。不得用 pass、NotImplementedError、固定返回成功、吞掉关键异常、睡眠模拟训练、随机动作冒充模型、空模型、假下载、假哈希、假签名、假进度或只更新版本号满足界面效果；正常算法中的随机抽样、可复现训练种子和有安全理由的幂等清理不属于伪实现。
2. 若单轮不能覆盖全部要求，必须优先交付可运行、可安全停止、不会损坏数据的真实纵向功能，并在后续迭代继续补齐；不得破坏已工作的路径，也不得声称未实现功能可用。
3. 实现优先级依次为：
   - Python 3.12 可启动、主界面、目录和互斥状态机；
   - Esc 紧急停止、输入释放、原子写入和数据安全；
   - “文件”真实校验、修复和隔离依赖；
   - “人”真实目标捕获与示范经验记录；
   - “升级”真实经验整理、训练、验证和发布；
   - “AI”真实推理、受限输入和看门狗；
   - 性能、迁移兼容和增强功能。
4. 每次修改都必须交付完整替换版 AnyGameAI.py，而不是补丁片段。
5. 当远程服务、真实模型资源或目标游戏能力不存在时，正确实现是保留最后有效状态、保持零输入并诚实报告；不得为了表面覆盖要求而编造外部条件。
